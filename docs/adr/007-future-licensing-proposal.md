## 1. 本文效力与已确定方向

本文是工程与产品授权要求的评审记录，不是许可证、商业合同、贡献者协议或法律意见；没有拟定可直接执行的自定义法律条款。本 PR 只新增本文与 ADR 索引入口，不替换或修改 LICENSE，不更改当前 README 的 MIT 声明，不重新标记历史版本，也不在产品中实现许可检查。本文自身随当前仓库按现行 MIT 发布，不因讨论未来授权而产生商业使用限制。

产品方向已确定：个人非商业使用永久免费；商业使用须取得单独商业授权；源码公开可见；普通个人用户无需注册账号或申请免费许可证；授权费用、计费尺度和报价均未制定。未来实施仍以有权主体批准、法律审核和单独切换 PR 为前提。**当前已发布及本次 PR 的内容仍适用现有 MIT 条件，不能要求其商业使用者补购授权。**

ADR-006 目前继续有效。本文只提出其“未来发行授权选择”部分的潜在后继方案；即使本 Proposal 文档被合并，也不构成 supersede 或授权切换。六层架构和运行时对象权限与商业产品授权是不同问题。

### 2.2 MIT 权利不能倒退

[MIT 正文](https://opensource.org/license/mit)允许商业利用、修改及再分发，需保留其规定的通知。旧版可被继续使用和合法分叉；本项目不通过重写历史、移动标签、删除发布或新公告追溯撤回既有 MIT 许可。后续安全支持可以有单独政策，但不能用停止维护变相要求旧版使用者付费。此预审不推断各司法辖区的个别争议结果。[ETH 的许可证管理指引](https://transfer.ethz.ch/researchers/oss/license.html)也区分已发布版本与未来版本。

MIT 允许符合条件地将旧材料用于新派生发行，并不通常要求为 MIT 已授予的再利用权限逐一补签；但不能因此抹掉旧通知、声称旧材料从未按 MIT 发布，或把新限制强加于已获 MIT 的副本。未来限制只能在有权授予且法律允许的材料/新贡献范围内设计；新组合发行的边界、通知布局及限制可执行范围由律师审核。用户仍可选择仅使用旧 MIT 部分。

## 3. 候选与推荐

| 候选 | 优点 | 与产品方向的差异/代价 | 预审结论 |
|---|---|---|---|
| 继续 MIT，销售支持/托管/企业功能 | 兼容性好、无许可门槛 | 不能要求所有商业利用另获许可 | 保留为旧版及不切换时的现状，不满足新产品目标 |
| GPL/AGPL + 商业例外 | 可选择双授权商业化 | copyleft 仍允许商业活动，不能仅因商业使用就要求购买 | 不满足本次目标；不以 copyleft 替代非商业限制 |
| 原样 PolyForm Noncommercial 1.0.0 + 商业许可 | 已有软件非商业文本，允许修改及分发 | 覆盖部分非商业组织，组织与受资助活动边界可能比本项目预期宽 | 首选交给律师做适配性审查；本轮不采用 |
| BUSL-1.1 + additional use grant + 商业许可 | 已有源可用框架 | 默认免费范围是非生产使用，且有到期转开放许可安排；与持续商业授权目标不完全吻合 | 非首选，不擅自删除标准文本约束 |
| Elastic License 2.0 + 商业安排 | 已有源可用文本 | 主要限制特定托管服务等，仍允许较多商业用途 | 不满足“商业使用须另获授权” |
| 经律师起草/审核的项目专用个人非商业许可 + 商业许可 | 可精确表达个人、商业边界及永久免费 | 法律成本、生态兼容与条款歧义风险最高 | 标准文本不匹配时的备用路径，不在此起草条款 |

比较依据：[PolyForm 正文](https://polyformproject.org/licenses/noncommercial/1.0.0)、[BUSL-1.1 正文](https://mariadb.com/bsl11/)、[Elastic License 2.0 正文](https://www.elastic.co/licensing/elastic-license)。PolyForm 的组织条款还可能涵盖受商业资金或任务约束的活动，必须按商业矩阵逐例审查，不能宣称原样文本已满足“所有商业使用另获授权”。PolyForm 原文的组织许可范围不能被 FAQ 悄悄缩窄；BUSL 也不能被描述成永久禁止一切商业使用。所有候选都未在本仓库生效。

推荐结构是“明确的公开使用许可 + 独立商业合同”的两条授权路径，先审查标准非商业文本能否完整满足产品目标。若要求只保证自然人非商业免费且对组织边界更严格，转交律师拟定/审核项目专用方案，而不是给 MIT 追加一句禁止商用。任何名称、SPDX/LicenseRef、适用主体、语言优先级和正文均待审核。

商业使用受限的未来版本应称 **Source-Available（源码可见）**，不宣传为 OSI Open Source；[OSI 定义第 6 条](https://opensource.org/osd)不允许限制商业等使用领域。公开 GitHub 仓库与开源许可不是同义词。当前 MIT 基线的开源属性不受此 Proposal 影响。

## 4. 商业边界：待审核的产品判定要求

以下矩阵是拟议判定用例，不是对当前 MIT 用户的限制，也不是正式法律定义。以活动目的、实际受益对象及预期商业应用为核心；不以营收是否到账、公司规模、部署位置、是否收费或账号类型单独判断。不设置营业额豁免或商业试用豁免。

| 场景 | 对未来受新许可覆盖材料的拟议处理 | 需明确的问题 |
|---|---|---|
| 自然人本地管理个人记忆、学习、私人娱乐、无商业目的的爱好 | 永久免费，无账号/申请/许可 key | 免费不以联网、遥测或每年重新确认作为条件 |
| 员工在公司设备上纯私人学习 | 不仅因设备/雇佣身份转为商业 | 活动目的及雇主利益应分离；设备政策仍由雇主决定 |
| 员工/团队用于企业内部知识、编码、运营或生产力 | 商业授权 | 内部部署、不开源、不对外收费均非自动豁免 |
| 自由职业者为客户交付、收费咨询或承接项目 | 商业授权 | 包括个人名义和间接提供服务 |
| 公司产品嵌入、OEM、付费插件、商业 SDK 集成 | 商业授权 | 合同须明确嵌入、分发及下游使用范围 |
| SaaS/API/托管服务、白标或代理运行 | 商业授权 | 免费套餐或广告引流仍可能服务商业目标 |
| 初创公司未营收、商业目的 POC/研发/测试 | 商业授权 | 预期商业应用足以触发拟议边界；暂无免费商业评估期 |
| 个人从无商业目的爱好转向销售产品/服务 | 转变前取得商业授权 | 不追收此前合规非商业期间费用，也不改变旧 MIT 权利 |
| 广告、赞助、平台打赏、成本分摊、众筹 | 需律师区分商业交换与无条件赠与 | 不把所有捐赠自动当商业，也不设置绕过商业实质的金额门槛 |
| 公益组织、大学、政府、公共研究及个人受资助研究 | 不在已确定的“个人非商业永久免费”保证范围内作推定 | 未营利不等于个人；选 PolyForm 可能明确允许其中多类。需确定组织非商业授权政策；不擅自宣称全部收费或全部免费 |
| 非商业开源协作、社区镜像、分发下载 | 依据第 5 节的拟议修改/分发授权 | 公司参与贡献、雇主出资及包管理镜像边界要单独确认 |
| 原 MIT 版本/独立旧版 fork 的商业利用 | 继续按既有 MIT，无新增商业许可要求 | 不能把新策略反向用于旧代码或回收其既有权利 |

该产品方向面向未来所有按本方案发行的正式版本：个人合规非商业使用不设置试用期或使用期限，不以未来版本改为订阅收费来绕过永久免费承诺；托管、支持等额外服务是否收费需另行说明，不能混同本地软件使用许可。

普通个人免费使用不需要上传身份、证明非商业、注册账户、申请“免费商业版”或获得人工批准。商业客户可能需要有权签约主体和合同联系信息，不能扩展成所有用户的强制账号体系。歧义通过清晰公开的正式边界处理，不用“所有个人都先来申请”代替定义。

## 5. 修改、再分发与数据的方案要求

以下均为待法律审核的目标，最终选择的标准文本若与之不同，必须先解决差异，不能靠本 ADR 解释改写标准许可证。

- 个人非商业路径拟允许查看、下载、离线运行、编译、学习、修改和备份；合规获得的指定版本不因未来收费政策变化被要求定期续费。软件维护/支持承诺与许可期限分开。
- 拟允许合规非商业目的的原版与修改版源码/二进制分发，保留适用许可、原有版权及第三方通知，清楚标示改动、来源 commit 和非官方身份。新限制不得被分发者去掉，也不能由分发者任意替下游签发商业例外；MIT 组成部分继续保留其已有权利。
- 源码公开可见是官方发行要求；镜像、公开 fork、二进制对应源码提供义务、是否要求发布个人修改、商业客户修改是否可闭源，均须在最终文本和商业合同中明确。推荐不强制发布纯私人修改；拟议公开再分发应提供可获得的对应源码。不能声称 PolyForm 自动包含这一额外源码义务。
- 出售分发包、商业服务中嵌入、OEM、再授权、转售及托管属于商业路径的合同范围；商业合同明确席位/实体/关联公司/服务商/地域/期限/版本与续订，但本轮不确定这些计费单位或价格。普通购买使用权不自动包含 OEM、转售或转授权权。
- 与 GPL/AGPL 等组件结合、新 SDK 的复制式模板/生成代码、可分离协议定义及示例的许可兼容性逐项审查；不声称“采用 adapter 就自动兼容”。如希望 SDK/契约独立宽松授权，应另行决定范围，不在本轮悄悄增加例外。
- 用户的事件、记忆、输入及输出不因软件许可自动转让给项目；不要求上传真实数据作许可审核。包含软件代码片段的生成物、模型/权重及第三方素材需分别评估。
- 商标、项目名称、专利、支持服务和数据使用权与代码版权分开处理，不把版权许可当作官方背书；不擅自给予自己并不持有的专利或商标权利。

## 6. 贡献者权利与未来入站授权

现有 MIT 内容按其许可复用并保留通知；集合署名不等于版权集中。在发布受限新材料之前，建立材料级来源台账：路径/commit、实际权利人、原创或第三方来源、原许可证、雇佣/委托关系、入站授权依据、AI 辅助情况及审查状态。身份与签署记录私密保存，公开仓库只放必要状态和通知，避免新增个人资料泄漏。

候选：版权转让（控制集中、贡献门槛高）/非独占 CLA（贡献者保留版权、可明确双路径授权）/仅 DCO（来源声明简便，但不能假定取得超出原许可的再授权权）。推荐律师审核的 **个人 CLA + 必要时雇主/法人授权**，以非独占方式取得对新贡献发布源可用许可及商业许可所需的明确权利，考虑修改、分发、再许可、必要专利范围、已授予权利的持续性及对个人免费承诺的约束。本文不提供 CLA 法律正文，也不要求补签当前代码才能继续合法使用 MIT。

[DCO 原文](https://developercertificate.org/)是贡献来源与提交权限的证明框架，不能仅凭 sign-off 宣称已签双许可 CLA。若未来采用不同入站许可证，不得无审核套用提到 open-source 许可的标准 DCO；必要协议和隐私流程须一并审查。[Apache 的贡献协议说明](https://www.apache.org/licenses/contributor-agreements.html)展示个人与法人权利需分别处理，但其 CLA 不能直接视为适用于本项目。

未来候选规则：未确认入站权利的新贡献不进入受限商业发行；不能把“提交了 PR”或维护者勾选状态当作完整商业再许可。贡献者若只愿按 MIT 提交，可以保持其 MIT 材料可分离并保留通知，或暂缓合入目标发行；不能谎称其材料具有独占商业限制。贡献者自己对原有创作保有何种使用权必须明确，不暗中转让版权。历史贡献缺少证明时先核实，必要时排除/替换不明确部分；不能靠重命名文件清洗来源。

## 7. 版本切换与兼容策略

1. 本次仅文档 Proposal，PR 保持待审，不合并任何生效许可证；不得变更 LICENSE、README 现行 MIT 标识、包元数据、旧 tag 或版本号。本次 PR/ADR 本身继续在 MIT 范围内。
2. 律师审核前明确有权发许可的自然人/法人、司法辖区、适用法律、商业矩阵和组织例外、个人永久免费承诺、违约补救、专利、商标及消费者保护。费用仍不制定。
3. 对所有准备进入新发行的材料及依赖完成权利台账、通知清单和贡献入站流程。任何在 MIT 下继续公开的新材料都会新增可按 MIT 使用的范围，不能事后仅凭版本号转为独占限制；后续开发/发行安排须在新实施任务中明确。
4. 单独实施 PR 才能提出最终审核文本和切换清单，获明确批准后选择首个未来版本及生效 commit。版本号、日期和首个受限 commit **目前全部待定**，不得把 `0.0.0-p0` 或 `arch/p0-baseline-001` 追溯改为新许可。用新 tag 表示新发行，不移动既有 tag。
5. 新发行逐文件/材料标明 MIT legacy、第三方许可和获授权的新材料，保留原通知；正式 LICENSE、README、包元数据、文档和发行页同步说明。是否使用 SPDX LicenseRef 及命名由最终文本决定，不把 Proposal 当作扫描器可识别的已生效许可。
6. 保留旧 MIT 版本可访问性和已发布历史；明确新旧版本边界、补丁/backport 的授权来源和支持周期。旧版 MIT 修复可以依其许可进入新版本；受限新贡献不能不经权利审核直接标为 MIT 回移到旧分支。对旧版 fork 不提追溯商用收费要求。
7. 即使新版本收费，个人仍可依据符合条件的公开许可离线使用，无免费许可证登记、激活服务器、周期性续签或跟踪非商业用户。许可合规与内核 tenant/space 数据授权相互独立；本轮不新增运行时遥测、断网锁定或远程销毁能力。

## 8. 工程验证与失败场景

验证范围分两类：本轮机械检查可证明修改范围、历史事实和同步状态；下列法律/产品场景只是一套审查输入，CI 通过不能证明条款有效、版权归属或跨法域可执行性。

| 编号 | 方法 | 必须满足/失败条件 |
|---|---|---|
| LP-01 本轮保护 | `git diff --name-only <base>...HEAD`；比较 `<base>:LICENSE` 与 `HEAD:LICENSE` 的 blob | 仅本文及索引变更；LICENSE、README、VERSION、旧标签及许可 metadata 不变；否则阻止本轮验收 |
| LP-02 历史边界 | 在 base 的全部可达提交读取 LICENSE；核对旧 tag peeled SHA 与表中基点 | 已发布 MIT 未改写；新授权不能被描述为旧用户必须接受 |
| LP-03 版权证据 | 来源台账模拟“不同作者/员工代码/第三方片段/AI 输出”四类输入 | 未明确权利不标为可独占授权；账户相同或 DCO 不能跳过核验 |
| LP-04 商业边界 | 用第 4 节每行作为法律评审用例，再加入“无收入公司、内部部署、个人受雇、捐赠、非营利机构”反例 | 每例有适用许可或明确待定，不能把模糊用例硬塞入永久免费个人或收费商业 |
| LP-05 免费承诺 | 未来实现时断网、无账号、无 key、跨年继续运行个人合规版本 | 仍可运行；需激活/申请/按年免费续签则不满足目标；本轮不实现该运行测试 |
| LP-06 发行追踪 | 未来构建 manifest/SBOM 对比实际包、源码与许可标识 | 不遗漏 MIT/依赖通知，不把整个旧代码声称为全新受限产权，不以换 tag 撤销旧许可 |
| LP-07 分发/贡献 | 公开修改 fork、纯私人修改、商业 OEM、仅 MIT 的外部 patch、未签雇主授权分别走流程 | 只授予具备权利的范围；最终文本与矩阵一致；不存在从通用 CLA 模板臆造权利 |
| LP-08 仓库质量 | README 的 pytest、mypy、ruff、安全扫描，staged/full-history Gitleaks，diff --check；PR baseline CI | 全部通过且 diff 人工审阅；没有秘密、签署资料或真实用户记忆进入公开 PR |
| LP-09 PR 同步 | 服务器读 PR head SHA 与 `ls-remote refs/heads/<proposal-branch>` 对比本地 HEAD；读取 PR CI、main 与旧 tag | proposal 分支已同步，main/旧 tag 不变；不得报告已经实施授权切换 |

LP-01/02/09 作为本轮一次性检查执行，不为纯文档措辞添加镜像实现的单元测试。未来实施 PR 的发行校验再按需自动化。

## 9. 待确认法律风险与实施阻断项

| 风险 | 当前结论 | 正式切换前所需确认 |
|---|---|---|
| 权利主体与完整权属链 | 只有集合版权行和提交账户证据 | 实际人/法人、员工/委托关系、第三方和 AI 辅助材料的可授权范围 |
| 旧 MIT 与混合发行 | 必须保留旧权利；旧 fork 可继续商用 | 新贡献限制的边界、派生整体与可分离 MIT 材料的通知及执行策略 |
| 商业目的歧义 | 个人/组织、间接利益、研发和赞助均有灰区 | 逐例定义；不能只看收费/营收，不把所有组织自动当作商业 |
| 标准许可证不完全匹配 | PolyForm 可能扩大非商业组织许可；BUSL/ELv2 目标不同 | 接受标准范围，或律师审核项目专用文本；不得在 FAQ 中缩窄正文 |
| 永久免费与后续版本政策 | 指定合规版本永久免费，无账号申请 | 明确承诺覆盖范围、变更与终止/补救、消费者保护，避免单方随意撤销承诺 |
| 入站协议与专利 | 无 CLA/雇主授权记录 | 非独占授权、必要专利、签署效力、隐私及协作流程；普通用户不签 CLA |
| 依赖和生态兼容 | 当前只是引用开发依赖，无完整产物许可审计 | 正式包/容器/SDK、copyleft、模板与文档/素材的具体许可相容性 |
| 跨司法辖区 | 尚未选法律或商业签约主体 | 律师按目标市场审查合同成立、限制可执行性、消费者及竞争/税务问题 |
| 商标与产品表述 | 源可见不等同 OSI 开源 | 未来官网/README/包标识一致；不虚构商标/专利权利 |
| 费用与商业合同 | 本轮未制定价格或收费单位 | 单独商业方案决策，不从本 Proposal 推导报价、SLA 或授权已售出 |

预审推荐可以进入独立 PR 讨论，**不能据此认定法律审核完成或正式授权已实施**。全部实施阻断项须在另行授权的切换任务中解决。
